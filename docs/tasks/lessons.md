# 经验与教训

- 用户指出重生成书册右侧仍有白边时，不能把 Alpha 包围盒一致、透明区 RGB 已清零当作“边缘干净”的证明；白边可能位于遮罩内部的书口像素。以后必须在深色底逐边观察实际合成结果，源 Alpha 只用于几何参考，不能盲目复用其边缘颜色；母版有任一亮边就停止批量生成并重做母版。
- 用户要求“扩写根 README”同时仍要求创建组件 README 时，不能把“扩写而非重写”误读成取消第二份文档；应分别确认每个目标文件的动作类型（保留并扩写 / 新建并详写），再锁定范围。
- 用户指出六张独立生成图导致翻页不流畅时，不能把“像素尺寸相近”和“同一提示词”当作同构证明；必须先从上游真实素材提取画布、书脊、页角、叠页、亮度、纸纹和边缘统计，以一张锁定母版驱动所有变体，并用自动一致性检查与浏览器中间帧共同验收。
- 用户要求题材多样化并强调“重新生成”时，不能把旧素材作为编辑底图或引用输入，也不能用统一视觉语言作为重复同类构图的理由；应将纸张、书脊、线条和色彩作为风格约束，从零生成不同题材，并把旧文件明确改名留作备用。
- 迁移开源交互后出现状态竞态时，应先回查并机械复用上游已经验证过的状态机与动画所有权，不先设计替代机制；只有上游确实遗漏的边界（如预载期输入）才做最小补充，并保持本站已批准的视觉参数不变。
- 用户反馈“布局仍然很大”时，不能只继续缩字号或 padding；必须同时测量容器实际高度、首屏后续内容露出量，并核对 CSS Grid 中相互覆盖的列是否被自动排到不同网格行。视觉叠放必须显式声明行关系，避免结构错误伪装成设计留白。
- 用户提供真实窗口截图后，不能继续用 1440px 计算字号上限证明“已经不大”；必须在用户实际宽屏比例下检查同屏视觉占比、书法字体墨量和换行形态。展示字的 CSS 像素只是输入，画面占比才是验收结果。
- 浏览器验收不能只检查无报错、无横向溢出或 DOM 已挂载；凡是入场揭示内容，都必须在滚动进入视口后断言计算样式已回到可见终态，并覆盖遮罩、子项和真实媒体。
- 大胆排版必须分别约束装饰字与承载信息的真实标题：装饰字可以裁切越界，真实标题仍需设桌面与移动端尺寸上限，不能让“视觉冲击”破坏阅读与内容密度。
- 用户要求“真正大胆”时，不能只把既有网格中的标题、编号、错位和 hover 分别加码；先检查去掉文案后的页面骨架是否仍有独特观看机制，再用一个统领全站的结构动作重做入口与章节接棒，并用真实浏览器首屏和跨页连续性证明差异。
- 线上页面持续加载且本机 TLS 工具异常时，先同时核对部署配置与独立网络结果；用户指定回退基线后立即停止原排查路径，精确核对目标提交和差异，再按指定基线重新验证。
- 用户明确要求远程同步回退时，先 fetch 固定远程现状，再用 `--force-with-lease`，推送后同时核对远程 SHA 与部署工作流状态。
- 用户重启系统后故障仍在，不能继续把“重启”当作结论；应把所有资源统一报 `ERR_CERT_DATABASE_CHANGED` 视为系统 TLS 基础设施故障，建立跨域 Schannel 反馈并查明持久配置或后台变更源。
- 用户确认 Edge 正常、Chrome 失败后，应立即把浏览器差分置于 Schannel 线索之前；命令行 Schannel 故障可能并存，不能据此把 Chrome 独有故障直接归因到全局系统 TLS。
- 对约定为硬链接的规则文件，不能只比较内容或沿用旧记录；应使用 `fsutil hardlink list` 核对当前文件关系。链接断开且用户指定主文件后，以主文件重建链接，再验证两个路径的文件 ID、哈希与 Git 差异。
- 用户询问网站“还缺什么”时，应先按其语境限定审查维度；用户明确只谈设计后，不再扩展到功能、产品流程或技术栈，只从构图、层级、色彩、字体、留白、图像与视觉节奏给出建议。
- 用户指出“有粒子但不明显”时，不能把 DOM 中存在动画当作视觉完成；应给出首屏可见数量、尺寸、透明度与观察时限等验收条件，并通过真实浏览器截图或录屏判断是否达到预期。
- 用户要求“建新分支提交改动”时，须先区分改动性质再定归宿：特性工作进分支，全仓基线类提交（行尾统一、格式化基线、CI 配置）应直接落在主分支，避免基线生效依赖特性分支的合并顺序。被纠正后用 cherry-pick 到主分支 + `rebase --onto` 从特性分支移除，并核对两侧文件归属与工作区行尾。
- 用户授权「修复/实施某项工作」不等于授权提交；git.md 明文「未经用户明确要求，不提交、不推送、不创建 PR」。每轮任务完成后的提交必须先获得用户明确的提交指令（一句“提交吧”即可），不能因为分支未推送、改动已验证通过、或沿用早前某次的提交授权而默认延展到后续任务。
- 与用户确认方案、方法和位置只表示需求已锁定，不等同于开始实施；在用户明确说“实现”之前，只能做只读研究、方案校准和样稿确认，不能提前修改项目文件。
- 用户要求“迁移不了就直接复制”时，应把原实现的几何、阈值、弹簧和光影算法视为受保护内核，只做机械适配；若重构损害保真度，应回退到原 JavaScript 嵌入方案，而不是以此为由取消功能或重新诠释交互。
- 复刻翻页仓库时必须先分清“参与翻折的纸页画面”与“静止的书本外壳”：原效果使用全幅纸页进入曲面，不能把带硬封底、书边和透明画布的整本书生成图直接塞进叶片。生成器若把透明棋盘烘进图片，也不能靠近似裁切掩盖；应重做为无外框的全幅纸页，由 CSS 负责圆角和外部阴影。
- 用户用建筑速写样图说明“书的质感”时，必须把题材与材质拆开：继续生成约定的水墨山水，只迁移样图的宣纸纤维、叠页、中缝、线条粗细和暖赭灰墨，不能把参考图的建筑主题一并误搬。生成后还要读取真实像素格式；黑底或棋盘若已烘焙进 RGB，必须重生为可直接参与翻折的全幅纸页，不能用 CSS 假装透明。
# 2026-08-28：透明画布同构还必须检查边缘白色污染

- 统一尺寸、Alpha 边界和书体母版仍不足以证明透明边缘干净；在浅色页面上不可见的低 Alpha 白色矩形，会在黑底预览和 3D 翻页中变成白边。
- 以后所有透明册页必须额外在黑 / 深色底上检查四周，并自动验证书体外的低 Alpha 像素和 RGB 白色污染；只修统一母版，不逐张手工清边。
