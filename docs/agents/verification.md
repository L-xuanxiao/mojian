# 验证流程

- 验证范围与改动风险匹配，不以"代码已写完"代替结果验证。
- 仅修改文档时，回读内容并执行差异检查；无需运行项目构建。
- 修改代码、配置、路由或项目结构时，至少执行：

```bash
pnpm check
pnpm build
```

- 涉及布局、交互、动画、导航、Storage 或响应式行为时，还须执行 `pnpm test`；关键回归测试位于 `tests/e2e/`，GitHub Pages 的 `quality` job 也会执行同一套门禁。

- 改动提交前执行 `pnpm format:check`（格式不符时先 `pnpm format` 自动修复）。
- 行尾已由根目录 `.gitattributes` 固定为 LF；不要在编辑器或脚本中改动行尾风格。
- 视觉/布局问题的复现要覆盖用户真实视口（宽屏 + 系统缩放，如 1707×735 @DPR1.5），不能只用标准无头视口（1440×1000 / 390×844）下结论；必要时经 CDP 附加用户实际浏览器验证。
- 涉及布局、交互、动画、导航或响应式行为变化时，应在实际浏览器检查受影响路由和必要视口，不能只根据代码或自动化测试判断效果。
- 开发服务器以后台进程方式运行（如 `pnpm dev` 放入后台任务），通过日志与状态检查确认可用，结束后停止。
- 无法完成某项验证时，明确说明未验证内容和原因，不伪造结果。
